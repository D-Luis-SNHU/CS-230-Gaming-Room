# CS-230-Gaming-Room
## Software Design Document

Expanding Draw It or Lose It from an Android app into a full web-based multiplayer game for The Gaming Room was all about fixing core architectural issues. The client needed a system that could handle games, teams, and players without running into duplicate names or memory leaks. To solve this, I designed a centralized backend in Java using the Singleton pattern for the GameService to ensure only one coordinator exists in memory, and the Iterator pattern to keep entity names unique. Laying out the documentation went really well, especially with mapping out the domain model and using an abstract Entity class to keep the code clean and DRY. Having that blueprint ready before writing any code made life so much easier because I already knew how classes like GameService should manage state and assign unique IDs. 
If I went back to change anything in the design, I would add sequence diagrams to better show how real-time WebSocket messaging and JWT reconnection flow between the browser and server. Designing this way always starts with looking at what the end user needs, like fast and reliable gameplay across any browser or phone, and using those needs to pick the right tech. Moving forward, my approach to building software will stay focused on planning out object-oriented models, picking smart design patterns, and picking solid infrastructure like containerized Linux before diving into the actual source code.
